# 1 为什么会出现CAN-FD？

随着总线技术在汽车电子领域被越来越广泛和深入的应用，特别是自动驾驶技术的迅速发展，汽车电子对总线宽度和数据传输速率的要求越来越高，传统CAN（1Mbit/s，8Bytes Payload）已难以满足日益增加的需求。

因此在2012年，Bosch发布了新的CAN FD标准 (CAN with Flexible Data Rate) ，CAN FD继承了CAN的绝大多数特性，如同样的物理层，双线串行通信协议，基于非破坏性仲裁技术，分布式实时控制，可靠的错误处理和检测机制等，同时CAN FD弥补了CAN在总线带宽和数据长度方面的不足。2015年6月30日，国际标准化组织（ISO）已经正式认可CAN FD，并无反对票通过ISO 11898-1作为国际标准草案。

# 2 什么是CAN-FD

CAN FD协议是由Bosch以及行业专家预研开发的，并于2012年发布。通过标准化对其进行了改进，现已纳入ISO 11898-1:2015。一开始的Bosch CAN FD版本（非ISO CAN FD）与ISO CAN FD是不兼容。

CAN FD具有以下4个主要优点：

增加了数据的长度：CAN FD每个数据帧最多支持64个数据字节，而传统CAN最多支持8个数据字节。这减少了协议开销，并提高了协议效率。

提高传输的速度：CAN FD支持双比特率：与传统CAN一样，标称（仲裁）比特率限制为1 Mbit/s，而数据比特率则取决于网络拓扑/收发器。实际上，可以实现高达5 Mbit/s的数据比特率。

更好的可靠性：CAN FD使用改进的循环冗余校验（CRC）和“受保护的填充位计数器”，从而降低了未被检测到的错误的风险。这在汽车和工业自动化等安全攸关的应用中至关重要。

平滑过渡：在一些特定的情况下CAN FD能用在仅使用传统CAN的ECU上，这样就可以逐步引入CAN FD节点，从而为OEM简化程序和降低成本。

实际上，与传统CAN相比，CAN FD可以将网络带宽提高3到8倍，从而为数据的增长提供了一种简单的解决方案。

二者帧结构差异如下：

1.RTR与RRS：RTR用于在CAN中标识数据帧和对应的遥控帧。**而在CAN-FD中，完全不支持遥控帧**，遥控帧的替代位RRS始终为显性（0）。

2.r0与FDF：在CAN中r0为保留位且呈显性（0）；而在CAN-FD中，该位更名为FDF并呈隐性位（1）。在r0/FDF位之后，CAN-FD协议新增了“3个新比特位”（即res、BRS、ESI）。值得注意的是，不兼容CAN-FD的节点会在检测到FDF位后生成错误帧。

3.res：这个新增的保留位与r0位的作用相同——即未来可能被设置为隐性（1）以表示新协议。

4.**BRS：全名为The Bite Rate Switch（比特率切换位），若被设置为0则表示CAN-FD报文以仲裁速率发送（最高1M bit/s）；若被设置为1则表示数据帧剩余部分将以更高比特速率发送（最高5M bit/s）。**

5.ESI：全名为Error Status Indicator（错误状态指示位），默认位0，即主动错误状态；当发送方进入被动错误状态是该位转为1。

6.DLC：在CAN-FD协议中，数据长度码（DLC）的4比特设计与经典CAN保持兼容，但扩展了更大数据帧的编码方式。如图所示：

7.SBC：The Stuff Bit Count（填充计数器）位于CRC字段之前，由3位格雷码和1个奇偶校验位组成。随后的固定填充位（Fixed Stuff-Bit）可视为第二个奇偶校验位。SBC的引入旨在提升通信可靠性。

8.CRC：在经典CAN中，循环冗余校验（CRC）为15位；而在CAN FD中，CRC扩展至17位（适用于16字节及以下数据）或21位（适用于20-64字节数据）。经典CAN的CRC段可能包含0至3个填充位，而CAN FD则固定插入4个填充位，以显著提升通信可靠性。
