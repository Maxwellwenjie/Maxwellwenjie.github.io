# 1. 启动流程概述

启动流程大概分为几个步骤：

---
- PBL运行
- XBL运行
- MIFS运行
- 启动脚本运行  
    下图为8295安全启动流程图：
    ![[Pasted image 20251203191504.png]]

1、SOC复位时，`PBL（主启动加载器，固化在SOC内部）`的代码首先运行，先初始化硬件（定时器、PRNG、时钟等），启用缓存和 MMU，加载XBL到内存并验证XBL，然后跳转到XBL的安全模块去执行。
2、XBL的安全模块跳转到非安全环境去执行`XBL_Loader`代码，加载`AOP、QTEE、MIFS`等镜像并验证，然后跳转到`QTEE`初始化安全世界的环境，然后退出安全世界，执行MIFS镜像的启动代码。
3、MIFS镜像的启动文件先运行`startup-sdx-perf`，然后运行qnx内核`procnto-smp-instr`。
4、qnx内核初始化完成后开始运行MIFS镜像的初始化脚本`/proc/boot/.init_script`，此脚本为`mifs.build.tmpl`在打包过程中创建，等下会详细描述。
5、`init_script`脚本先初始化环境，运行一些必要服务之后，运行startupmgr。
6、`startupmgr`加载和验证ifs2镜像，运行一些启动优先级较早的服务。
7、`startupmgr`挂载`firmware、persist、qtd、system、oem`等分区。
8、`startupmgr`执行system分区的startup.sh脚本。
9、`startup.sh`脚本调用`vmm_service`，`vmm_service`内部调用`qvm`运行`android`。  
上图出自`《80-38358-1_REV_AB_SA8155_SA6155_SA8295_SA8195_Secure_Boot_-_QNX_Hypervisor.pdf》`，大家可到高通网站上查看。

下图为QNX BSP启动流程图：
![[Pasted image 20251203191656.png]]

下图为QNX文档描述的启动流程，它从QNX系统的视角来描述启动流程：  
![[Pasted image 20251203191724.png]]
1. 电路板硬件和固件执行检查和初始化任务，然后将控制权交给位于预定位置的软件。
2. `IPL`为初始程序加载器，对应高通的XBL模块。
3. `IPL`加载mifs后运行`mifs`的`startup`程序。配置系统，包括定时器、中断控制器和缓存控制器。配置完成后，该程序会将控制权移交给操作系统内核。
4. 内核即`procnto-smp-instr`启动。
5. 内核会调用由`buildfile`生成的`mifs`的初始化脚本、ifs2的各种服务。
6. 由`SLM`（系统加载和监控，类似于`lpEM`的进程管理程序）加载由SLM配置管理的进程。
7. 启动人机界面。  
    具体细节可参考qnx文档：[intro_startup_sequence](https://www.qnx.com/developers/docs/7.1/#com.qnx.doc.neutrino.building/topic/intro/intro_startup_sequence.html)

## 2.2 如何生成ifs镜像

在构建阶段，构建脚本先使用`filepp`工具把`mifs.build.tmpl`文件生成`mifs_la.build`，然后用`mkifs`工具生成`mifs_la.img`。  
详细可查看qnx仓的构建脚本和qnx官网文档：[buildfiles](https://www.qnx.com/developers/docs/7.1/#com.qnx.doc.neutrino.building/topic/buildfiles/buildfile.html)

```sh
filepp -imacros "fileperm.cfg" -imacros ./variant_config/8540.cfg  -imacros mod_soc_variant.cfg -D__IMAGEFS__ -D__VARIANT_DISP__ -D__VARIANT_AUDIO__ -D__VARIANT_CAM__ -D__VARIANT_PART__     -D__VARIANT_DISP__=DISP_COMMON -D__VARIANT_AUDIO__=AUDIO_COMMON -D__VARIANT_CAM__=CAM_COMMON -D__VARIANT_PART__=PART_COMMON -D__VARIANT_hyp__="-qvmhost" -DVARIANT_qvmhost     -D__VARIANT__=la -D_VARIANT_EXT_= -D__TOOLCHAIN_HYP710__ -D__CAMERA___ -D__SECURE_BOOT_QTD__=0 -D__SECURE_BOOT_QVB__=0     -D__SECURE_BOOT_SECPOL__=1 -D__IFS2_ENABLE__=1 -D__KM_INDEPENDENT_QVB__= -D__PERF_ENABLE__=0 -D__SLM_ENABLE__=0 -D__DEBUG_UEFI_REMOVAL__=0     -D__ENABLE_QCPE_QHEE__= -D____ -D____ -I~/code/SA8295P_QNX_V901/apps/qnx_ap/target/filesets -I -I~/code/SA8295P_QNX_V901/apps/qnx_ap/install/usr/include -I~/code/SA8295P_QNX_V901/apps/qnx_ap/target/hypervisor/host ~/code/SA8295P_QNX_V901/apps/qnx_ap/target/hypervisor/host/build_files/mifs.build.tmpl > ./out_8540/mifs_la.build

```

### 2.2.2 生成启动程序
---
可启动操作系统镜像中的第一个程序是启动程序，其目的是初始化硬件、初始化系统页、初始化外部调用，然后加载内核并将控制权移交给内核（`procnto`或 `procnto-smp`）。如果操作系统镜像不在 RAM 的最终目标位置，启动程序会将其复制到该位置，并在需要时进行解压缩。  
启动过程中，内核会初始化内存管理单元 (MMU)，创建用于处理页面映射、进程和异常的结构，并启用中断。此阶段完成后，内核即可完全运行，并开始从启动脚本加载和运行用户进程。

语法中规定文件名为`.bootstrap`的文件为启动引导程序，构建时生成`startup.*`文件放入镜像文件中。  
下面是8295的`mifs_la.build`的`.bootstrap`部分的内容：

```none
# apps/qnx_ap/target/hypervisor/host/buildfile_parse/mifs_la.build  .bootstrap
[uid=0 gid=0 perms=0755]
[+keeplinked]
[-optional]
[image=0xA0000000]
[virtual=aarch64le,raw-qc] .bootstrap ={
    # startup options.
    # -P : Number of cores to bring out of reset.
    # -L : Load LK.
    # -l : Load IFS2.
    # -d : Disable QHEE reflection of SMC. //
    # -Z : Enable QTIME_FLAG_TICKLESS
    # -O : Device Tree Overlay type
    #     -O0 : Disable Device Tree Overlay
    #     -O1 : Device Tree Overlay based on Flavor ID
    #     -O2 : Device Tree Overlay based on DDR Size
    # -s : Disable Syspage Validation
    # -H : Enable raw oem data
    # -w : Enable Write Protect for UFS
    [+keeplinked module=fdt_config] ./startup-sdx-perf  -P8 -O0 -l -U -w

    # the PATH and LD_LIBRARY passed to procnto are not passed to the bootscript , but instead the  _CS_PATH and _CS_LIBPATH are set which are then used by login.
    [+keeplinked module=qvm module=pctrace uid=0 gid=0 perms=0700] PATH=/ifs/bin:/ifs/usr/bin:/ifs/usr/sbin:/ifs/sbin:/mnt/scripts LD_LIBRARY_PATH=/ifs/lib64:/ifs/lib64/dll:/ifs/usr/lib:/ifs/usr/lib64:/ifs/lib:/lib64:/lib64/dll:/usr/lib:/usr/lib64:/lib:/mnt/lib64:: DEBUG_RINGBUFFER=ringbuffer procnto-smp-instr -ae -bl -mL~xr -F 4000 -~s
}
```


从上面的内容可以看出，`mifs`把`startup-sdx-perf`放到了`startup.*`中，同时确定了启动内核的命令和参数。详细参考QNX官方文档：[nto_bootstrap](https://www.qnx.com/developers/docs/7.1/#com.qnx.doc.neutrino.building/topic/buildfiles/nto_bootstrap.html)  
`startup-sdx-perf`在`xbl`加载`mifs`镜像后会自动运行。  
`startup-sdx-perf`和`procnto-smp-instr`均不开源，存放路径分别为：

```none
./prebuilt/aarch64le/boot/sys/startup-sdx-perf
/opt/qnx/qnx710_7.1/target/qnx7/aarch64le/boot/sys/procnto-smp-instr
```


### 2.2.3 生成proc/boot/.init_script

初始化脚本在`buildfiles`的语法：

- 在文件的属性中使用script关键字进行修饰。
- 可分为几个文件来描述脚本，文件名的格式为`*_script`，其中`.init_script`描述最早执行的部分；`.end_script`描述最后执行的部分，其他为中间执行的部分。

# 3. startup.sh启动流程分析

## 3.1 [如何生成startup.sh](http://xn--startup-215ki07e0rtn31c.sh/)

在`apps/qnx_ap/target/hypervisor/host/startup.qvmhost.tmpl`模板文件中修改脚本内容，在构建阶段`filepp`工具把模板文件生成`startup-qvmhost.sh`

```sh
filepp -I${FILESETS} -imacros ${FILESETS}/secpol/system_uids.txt -imacros ${FILESETS}/secpol/system_gids.txt -imacros ${SOC_CONFIG} ${SOC_VARIANT} -I${FILESETS} -D__TOOLCHAIN_${qnx_toolchain}__ -D__VARIANT_hyp__="qvmhost" ${BSP_ROOT}/target/hypervisor/host/$startup_file.qvmhost.tmpl > ./${OUT_DIR}/$startup_file-qvmhost.sh
```

使用`grep`命令搜索，可以看到`startup-qvmhost.sh`最终被打包到`system`镜像的`scripts/startup.sh`文件中。  
阅读`startupmgr`的源码可以看到`system`分区被挂载到`/mnt`目录，所以`startup.sh`在板子上的完整路径为`/mnt/scripts/startup.sh`。

```shell
grep -rns "startup\-qvmhost.sh"
filesets/qc.scripts.build:8:PERM_BIN scripts/startup.sh=${OUT_DIR}/startup-qvmhost.sh

grep -rns "qc.scripts.build"
hypervisor/host/build_files/system.build.tmpl:54:#include "qc.scripts.build"
```
